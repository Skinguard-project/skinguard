DEVELOPMENT

We improved SkinGuard by changing how data was collected

The most important lesson was not “collect more data.” More data only becomes useful when measurement conditions and quality controls are stable enough to support comparison.

01 · EARLY APPROACH

Recruit users and gather readings

The project initially prioritized obtaining more measurements and images to develop the system and test the concept.

02 · WHAT FAILED

Some records could not be compared

Differences in measurement conditions, workflow, context, and consistency reduced the value of part of the collected data.

03 · REDESIGN

Build quality before scale

The workflow shifted toward calibration, context fields, measurement-quality checks, repeatability, and clearer instructions.

04 · NEXT TEST

Expand data under stronger controls

Phase 2 will collect substantially more longitudinal user-use data to test personalization hypotheses and weather context.

DESIGN PRINCIPLE

“Works once” is different from “reliable in real life.”

Real-world engineering must account for variation in users, devices, environments, and routines. SkinGuard’s roadmap treats repeatability and usability as core technical problems.

“The breakthrough was not simply adding a more complex model. It was improving how information entered the system.”

Project development principle

DETAILED ROADMAP

What we need to test in each phase

The roadmap is more than a feature list. Each phase requires a different kind of evidence.

PHASE 1 · COMPLETED

Integrated prototype and preliminary validation

Built

Sensing, environment, image AI, Android app, SCI, records, calibration and feasibility workflow.

Question tested

Can the system complete end-to-end records, and which conditions make readings non-comparable?

PHASE 2 · H1 2027

Expanded user data and personalization validation

Planned work

Larger longitudinal dataset, individual baselines, personalization functions, weather forecast integration.

Question to test

Does individual history improve trend interpretation, and which functions are stable, understandable, and useful?

PHASE 3 · H2 2027+

Repeatability, reliability and product readiness

Planned work

Consistency, usability, security, cost, enclosure, manufacturability, maintenance, and expanded field validation.

Question to test

Can the system work consistently across devices, users, and realistic operating conditions?
